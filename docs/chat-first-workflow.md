# Chat-First Workflow

## 目标

`/deepwork` 是普通用户的主入口。

它的目标不是把用户带到一组终端命令里，而是让用户在 Codex 对话中完成：

- 进入 workflow
- 选择运行模式
- 提供目标
- 自动拆分任务
- 自动路由执行
- 审查结果并继续推进

---

## 首次激活

当用户输入：

- `/deepwork`

插件应优先进入简短引导，而不是先给命令。

建议询问的内容：

1. `Codex-first / CLI-first / Hybrid`
2. `显式 goal 驱动 / 更自主地自动拆分`
3. `普通 review / 严格 review`

每个选项都应该带一句简短说明，方便用户快速判断：

- `Codex-first`：尽量留在 Codex 内推进，适合更想要对话式协作的用户
- `CLI-first`：优先调用外部 CLI worker，适合更看重工具执行能力的用户
- `Hybrid`：按任务类型自动分流，适合大多数用户
- `显式 goal 驱动`：先由用户给出明确目标，再开始执行，控制感更强
- `更自主地自动拆分`：由 workflow 主动拆解任务并推进，适合想少管细节的用户
- `普通 review`：保留基本审查，推进更快
- `严格 review`：完成前增加更多检查，更稳但更慢

---

## 推荐对话形态

示例：

1. 用户：`/deepwork`
2. 插件：说明当前将进入结构化 workflow
3. 插件：询问偏好模式，并给每个选项一行说明
4. 用户：选择模式
5. 插件：复述模式和行为
6. 插件：请求第一个任务
7. 插件：开始自动推进

可直接采用的对话模板：

```text
你已进入 /deepwork。

先确认这次的工作方式：

1. Codex-first：尽量留在 Codex 内推进，适合更偏对话式协作
2. CLI-first：优先调用外部 CLI worker，适合更依赖工具执行
3. Hybrid：按任务类型自动分流，适合大多数情况

再确认推进方式：

1. 显式 goal 驱动：你先给清晰目标，我再开始执行
2. 更自主地自动拆分：我先拆任务并主动推进

最后确认审查强度：

1. 普通 review：更快推进
2. 严格 review：完成前做更多检查
```

## 记忆与再次进入

如果用户已经用过 `/deepwork`，下一次进入时应先复述最近一次偏好：

```text
当前默认是：Hybrid + 更自主地自动拆分 + 普通 review。
要继续沿用，还是这次切换？
```

如果用户说切换，再重新给出上面的简短选项说明。

## 偏好持久化规则

`/deepwork` 应记住用户最近一次明确确认的默认偏好。

建议长期记住这 3 个字段：

1. `执行模式`
2. `推进方式`
3. `审查强度`

可对应为：

- `Codex-first / CLI-first / Hybrid`
- `显式 goal 驱动 / 更自主地自动拆分`
- `普通 review / 严格 review`

### 首次进入

第一次使用时，应完整询问这 3 项。

### 再次进入

再次进入时，不应重新从零问起，而应先复述默认值：

```text
当前默认是：Hybrid + 更自主地自动拆分 + 普通 review。
要继续沿用，还是这次切换？
```

### 局部切换

如果用户只修改其中一项，就只更新那一项。

例如：

- 原默认：`Hybrid + 更自主拆分 + 普通 review`
- 用户说：`这次切到 CLI-first`

则新的默认变成：

- `CLI-first + 更自主拆分 + 普通 review`

### 会话级临时覆盖

有些切换不应该改写长期默认，而只对本次生效。

当用户表达这些意思时，应视为临时覆盖：

- “这次先用 CLI-first”
- “只在这个任务里严格一点”
- “临时改成显式 goal”
- “这次先别自动拆分”

此时应：

1. 在当前 `/deepwork` 会话中应用新设置
2. 不改写长期默认
3. 明确告诉用户这是“仅本次生效”

### 明确记住

如果用户明确说：

- “以后都按这个来”
- “记住这个偏好”
- “把这个设成默认”

才应将新的组合写成长期默认。

## 建议保存位置

从产品边界上看，这类偏好应属于用户级 workflow 配置，而不是 README 里的抽象概念。

建议保存范围：

- `~/.codex/codex-workflow/`

后续如果真正做落盘，可独立成偏好文件，而不要和 task state 或 batch state 混写。

详细的实现导向规则见：

- [Preference Persistence](./preference-persistence.md)

## 普通用户与高级用户边界

普通用户：

- 使用 `/deepwork`
- 在对话中完成偏好选择
- 只关心目标、进度和结果

高级用户：

- 使用 CLI 调试 runtime
- 修改 hook / preset / routing config
- 手动查看 batch / task 状态

CLI 相关内容见：

- [Advanced CLI](./advanced-cli.md)
