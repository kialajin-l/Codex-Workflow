ADVANCED CUSTOMIZATION

Hooks, presets, and mixed execution modes

Codex Workflow is not a hard-coded pipeline. You can inject skills, swap executors, add lint gates, change MCP scope, and route roles between CLI workers and Codex-managed tasks.

workflow-load / workflow-save / run-batch --resume
task.before_dispatch.json
Use dispatch hooks to route architect work into Codex, keep implementers on fast CLI workers, and inject skill contracts only where they matter.
{ "event": "task:before_dispatch", "default_exec_mode": "cli", "rules": [ { "when": { "route.role": "architect" }, "then": { "exec_mode": "codex" } }, { "when": { "route.role": "implementer" }, "then": { "executor": "opencode", "inject_skill": "lint-gate.md" } } ] }
Workflow preset flow
Treat presets as reusable policy bundles: load a baseline, modify hooks, validate behavior, then save a new workflow for teams or projects.
STEP 01 Load `workflow-load --name lint-gate`
STEP 02 Edit Adjust hook rules, executor mapping, skill injection.
STEP 03 Run Validate with `run-batch`, inspect review, logs, and cost.
STEP 04 Save `workflow-save --name my-workflow`
task.after_result.json
Apply hard gates after worker execution. Current actions support `lint`, `block`, and rule-based rejection with explicit reasons.
{ "event": "task:after_result", "rules": [ { "when": { "route.role": "debugger" }, "then": { "action": "lint" } }, { "when": { "goalIncludes": "lint error" }, "then": { "action": "block", "reason": "lint check failed" } } ] }
Resume and state recovery
Batches persist to `.workflow-state/`. If a run is interrupted, resume only touches tasks that are neither `completed` nor `blocked`.
# inspect node dist/index.js status --batch <batch-id> # recover only pending tasks node dist/index.js run-batch --resume <batch-id> # persisted artifacts .workflow-state/batch.<id>.json .workflow-state/<task-id>.json .workflow-state/logs/workflow-YYYY-MM-DD.log
